# 차량 인증 건너뛰기와 관리자 사용성 검토

검토일: 2026-11-16. 사용자가 전체 회원 공통 ON/OFF를 선택했다. 사진·OCR만 선택적으로 생략하며 개인정보 동의·차량번호·관리자 승인은 유지한다. 이미 면제로 승인된 차량은 필수 정책 복원 후에도 유지하고 신규·변경 차량부터 새 정책을 적용한다.

## 수정 전 확인한 동작

- `ProfileSetupScreen._canSave`는 신규 차량 입력 시 사진/OCR 결과를 요구한다. 동일 차량의 승인 회원 닉네임 수정만 예외다.
- `ConsoleMembers`는 프로필·동의·`vehicleVerified`를 모두 만족해야 회원 승인 버튼을 활성화한다.
- `ConsoleVehicleVerify`는 사진이 있는 회원을 표시하며 OCR 일치·동의가 있어야 차량 승인이 가능하다.
- 별도 서버 저장소 `D:/vsCodeProg/APT-Prj`의 `api/profile.js`, `api/users.js`, `api/auth.js`, `docs/resident-community-api.md`를 읽기 전용으로 확인했다. 서버도 차량 제출·승인 및 로그인 단계에서 인증 상태를 검사한다. 현재 확인한 계약에는 관리자 인증 건너뛰기 옵션이 없다.
- 따라서 화면 버튼만 해제하는 변경으로는 기능이 완성되지 않는다. 앱·서버·DB·웹 인증 흐름의 계약을 함께 정해야 한다.

## 인증 면제 방식 비교

| 방식 | 사용 흐름 | 장점 | 고려할 점 |
| --- | --- | --- | --- |
| 전체 설정 | 운영 설정에서 차량 사진·OCR 인증 필수 여부 변경 | 모든 회원에게 동일한 정책 적용, 가입 단계 단축 | 기존 대기 회원과 다시 필수로 바꿀 때의 처리 필요 |
| 회원별 면제 | 회원 카드에서 대상 차량의 인증 면제 | 기존 정책을 유지하면서 개별 문제 해결 | 사진 제출 전 가입 화면에 막힌 회원도 조회·면제 가능해야 함 |
| 둘 다 | 전체 정책과 회원별 예외 지원 | 운영 선택 폭이 넓음 | 정책 우선순위와 화면·검증 범위 증가 |

사용자는 첫 번째 방식인 전체 회원 공통 ON/OFF를 선택했다. 회원별 독립 면제 버튼은 이번 범위에 포함하지 않는다. OFF 상태에서 관리자가 회원을 최종 승인할 때 해당 차량의 정책 면제를 기록한다.

## 채택한 설계

- 사진·OCR 인증만 생략한다. 개인정보 동의, 닉네임, 올바른 차량번호 한 개 입력, 관리자 회원 승인은 유지한다.
- 실제 인증 완료와 관리자 정책에 따른 면제를 별도로 표현한다. OCR 일치나 사진 심사 완료를 허위로 기록하지 않는다.
- 서버가 현재 정책과 승인 가능 여부를 결정한다. 정책을 조회하지 못했거나 구형 서버가 정책을 제공하지 않으면 기존 필수 인증 흐름을 유지한다.
- 신규 가입, 차량 변경, 기존 인증 대기, 로그인 복원, 보호 API의 접근 검사를 같은 기준으로 맞춘다. 면제는 승인 당시 차량에만 유효하며 차량 변경 또는 명시적인 차량 승인 취소 시 해제한다.
- 기존 회원·차량 제출 버전 검사를 보존한다. 정책 수정도 충돌을 감지하고 저장 성공 응답으로 화면을 갱신한다.
- 전체 정책을 다시 필수로 전환할 때는 이미 승인된 면제 차량을 유지하고 이후 신규·변경 차량부터 적용하는 안을 권장한다. 기존 승인 회원을 일괄 재인증시키려면 별도 범위로 결정한다.
- 정책 변경·개별 면제의 수행자, 대상, 시간, 변경 전후를 서버 활동 이력에 기록한다. 사진 보관·삭제는 기존 계약을 보존하며 면제 적용 시 기존 대기 사진 처리도 서버에서 정의한다.
- 서버 API·DB·웹 확장은 별도 저장소에서 구현했다. 계약은 `D:/vsCodeProg/APT-Prj/docs/vehicle-verification-policy-api.md`를 따른다. 운영에는 아직 적용하지 않았다.
