# 현재 주차 차주와 선택적 앱 음성통화

요구: 전화번호 없이 인터넷 음성통화. 수신자는 현재 주차 등록 차주만 가능하며 차주는 주차 건별 수신 여부를 선택한다. 기존 배포 작업을 취소한 요청이 아니므로 닉네임/단일 번호판 변경의 배포 준비는 계속한다.

## 제안 화면과 동작

사용자 확인(2026-10-21): **권장 설계로 구현하고 TURN 설정 후 활성화**. 주차 건별 기본 꺼짐을 유지한다. 설계 검토에서 등록과 동의의 저장 순서, 백그라운드 종료, 연결 정보 안내를 추가했다.

등록 시 켠 경우에도 주차 저장 → 서버 발급 등록 ID 확인 → 전용 소유자 수신 설정 성공 순서로 처리한다. 설정 실패 시 저장된 주차는 유지하고 수신은 꺼짐으로 표시하며 실패를 안내한다. 잠금·앱 백그라운드·계정 전환 시 마이크와 연결을 해제한다. 음성 및 연결 정보를 통화에 사용하며 앱에서 녹음하지 않음을 안내한다. relay-only 연결로 설정하고 단기 TURN 자격 증명만 사용한다.

```text
주차 등록 / 내 주차 상세
[ ] 이번 주차 중 앱 음성통화 받기 (기본 꺼짐)
앱을 열고 있을 때만 통화할 수 있습니다.

다른 회원의 주차 상세
[차주에게 앱 통화] (현재 주차 + 차주 수신 허용 시 표시)
  요청 중 → 상대 수락 → 연결 중 → 통화 중
  취소 / 음소거 / 스피커 / 종료

차주 화면
주차면 관련 통화 요청: [거절] [수락]
수락하기 전에는 마이크를 켜지 않습니다.
```

QR 자동 등록도 기본 수신 거절이다. 현재 주차 소유자만 허용을 변경하며 관리자 타인 주차 편집으로 허용을 켤 수 없다. 출차·차주 교체·수신 해제 시 새 요청을 거절하고, 진행 중인 연결도 짧은 서버 lease/heartbeat를 통해 클라이언트가 종료한다. 본인 차량·비회원·미승인 계정은 통화를 요청하지 못한다.

## 구현 가능성과 선택지

1. 권장: flutter_webrtc 음성 + 기존 REST/DB 신호 교환 + 설정된 TURN 중계. 초기 범위는 양쪽 앱이 화면에 열린 상태다. 수신 동의·실제 수락·마이크 권한을 분리한다. 녹음하지 않는다.
2. TURN 없이 공개 STUN 기반 연결 시험. 같은 네트워크 등에서 연결할 수 있으나 통신사망/NAT 조합에 따라 실패하므로 일반적인 운영 통화로 보장하지 않는다.
3. 백그라운드/잠금화면 전화까지 포함. CallKit/Android 통화 서비스·푸시 수신 등 별도 플랫폼 작업과 실기기 검증이 필요하다.

운영 환경의 변수 이름 조회 결과 현재 TURN/STUN/RTC 관련 설정은 없다. 안정적인 통화에는 TURN 주소와 서버의 단기 자격 증명 발급 설정이 필요하다. 새 서비스 계정이나 유료 자원을 자동 생성하지 않는다. TURN 설정이 준비되지 않으면 권장안의 통화 기능은 비활성 상태로 유지하며 완료된 운영 통화라고 보고하지 않는다.

## 서버 경계

각 현재 주차에 서버 발급 opaque parkingRegistrationId를 부여한다. 기존 주차와 새 주차는 callAllowed=false로 시작한다. 일반 주차 상태 저장이나 타인 수정은 이 서버 값을 복사해서 보존하며 클라이언트가 수신 권한을 덮어쓰지 못한다. 전용 소유자 설정 요청만 opt-in을 바꾼다.

통화 요청은 slotId/expectedParkingRegistrationId/expectedStartTime을 받고 실제 수신 이메일은 서버가 결정한다. 호출·수락·신호·heartbeat·조회에서 현재 주차·소유 계정 생성 시각·동의·양쪽 세션을 확인한다. 타인 이메일을 마스킹하는 기존 state 조회를 보존한다. 중복 요청 키, 발신 제한, 참가자당 동시 1통화, 요청 만료를 둔다. 참가자 외 관리자도 SDP/ICE를 조회하지 못한다. 음성은 녹음하지 않고 임시 SDP/ICE는 종료 후 정리한다.

## 검증과 미결정

자동 검사: 수신 기본 거절, 소유자 외 변경 거절, 새 주차 식별자 교체, 출차/수신 해제/계정 전환 후 요청·신호 거절, 타인 통화 조회 차단, 중복/시간초과 및 리소스 해제. 실제 서로 다른 Wi-Fi/LTE의 Android/iOS 기기 2대에서 양방향 음성 검증이 필요하다.

결정: 권장 방식으로 구현하고 TURN 구성 전까지 꺼둔다. 외부 중계 서비스 선정·계정/자격 증명 생성은 아직 정해지지 않았다. 임의의 공개 TURN 자격 증명을 제품에 넣지 않는다.
