# APT 앱 안정성 개선 설계

사용자가 2026년 10월 9일 개선 항목 전체 진행을 승인했다. 기존 Flutter/Provider/Dio 구조와 현재 작업 폴더의 사용자 변경을 유지한다.

## 동작과 경계

- 인증 상태·회원 식별자가 바뀌면 주차 Provider가 동기적으로 이전 메모리 상태와 요청 세대를 무효화한다. 비회원 상태에서는 폴링을 중지하고 회원 캐시를 지운다. 회원 캐시는 소유자 이메일과 연결해 다른 계정에서 복원하지 않는다.
- 비동기 조회·저장·오류·롤백은 시작 당시 세대가 현재 세대와 같을 때만 적용한다. 게스트 진입은 즉시 빈 공개 상태로 전환하며 회원 데이터를 유지하지 않는다. 앱이 종료되거나 백그라운드에 있으면 폴링을 재시작하지 않는다.
- 로그아웃은 즉시 인증 UI에서 빠져나오고 서버 성공·서버 거절·네트워크 오류 모두 로컬 쿠키와 ETag를 정리한다. 진행 중인 인증 복원이 로그아웃이나 게스트 선택을 되돌리지 않게 한다.
- 초기 링크와 실행 중 링크를 하나의 슬롯 ID 보관/알림 경로로 처리한다. 회원 홈은 갱신된 주차 상태로 슬롯 등록 조건을 검사한다. iOS BLE는 iOS 권한 경로와 설명 문구를 사용한다. OS 링크 연결에 필요한 서버 association은 앱 코드에서 대신 배포하지 않는다.
- 개발 환경은 CI와 같은 Flutter 3.41.6을 사용한다. 미사용 의존성과 초기 문서를 실제 코드에 맞춰 정리한다. 운영 서버 쓰기·스토어 배포는 이번 검증에 포함하지 않는다.

## 검증

제어 가능한 HTTP 어댑터와 완료 신호로 늦은 조회·저장, 모드 전환, 로그아웃 오류를 재현한다. 테스트 실패를 확인한 뒤 최소 수정하고 전체 테스트·정적 분석·가능한 Android debug 빌드를 실행한다. 플랫폼 권한 및 링크 설정은 파싱/라우팅 테스트와 설정 검사로 확인하고, 실제 BLE·Google 로그인·OS 링크 진입은 실기기 확인 항목으로 남긴다.
