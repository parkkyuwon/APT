# APT 프로젝트 전체 분석과 개선 우선순위

기준일은 2026-10-21이다. Flutter 앱 `D:/vsCodeProg/APT-APP`과 연결 서버·DB·기존 웹 클라이언트가 있는 `D:/vsCodeProg/APT-Prj`를 대상으로 한다. 기능 추가보다 **재가입 삭제 경합, 관리자 전체 상태 덮어쓰기, 앱의 응답 순서 처리**를 먼저 보완하는 것이 좋다. iOS 출시에는 로그인 설정과 플랫폼 검증이 추가로 필요하다.

후속 작업에서는 사용자 승인으로 최우선 네 가지와 Android 전경 NFC를 로컬 소스에 구현했다. iOS 작업은 사용자 후속 지시로 전부 보류했다. 아래 항목은 감사 당시의 발견 기록이며, 최신 구현·검증·운영 미적용 상태는 [후속 검증 기록](../verification/PRIORITY_FIXES_NFC_2026-10-21.md)을 따른다.

## 분석 범위와 판단 기준

구조도·JSON 색인에서 인증, 주차, HTTP, 저장소, OCR, 커뮤니티, 통화, 플랫폼, 빌드의 연결을 확인하고 주요 소스·API·SQL·테스트를 검토했다. 앱에는 Dart 소스 96개, 테스트 파일 45개가 있다. 기존 웹은 프로필 등 앱과 계약을 공유하는 경계를 확인했으며 모든 웹 화면을 실행 점검한 것은 아니다.

- **코드 확인:** 소스에서 문제가 발생할 수 있는 경로를 확인했다. 경합 항목은 재현 순서를 설명했지만 이번 감사에서 실행 재현하지 않았다.
- **개선 제안:** 현재 의도된 동작이나 확장성을 보완할 항목이다.
- **미검증:** 실제 기기 또는 외부 운영 설정을 확인해야 판단할 수 있다.
- P1은 데이터·인증 신뢰성 또는 플랫폼 출시 전 우선 조치, P2는 안정성·개인정보·품질 개선, P3는 유지보수 개선이다. 이번 검토에서 P0에 해당하는 근거는 확인하지 못했다.

이번 작업은 분석 문서만 추가한다. 앱·서버 소스, DB, 배포 설정은 변경하지 않는다. 시작 당시 기존 수정·미추적 파일을 보존했다. 메모리 여유가 약 1GB인 환경에서 무거운 빌드·테스트를 추가 실행하지 않았으며, 정적 분석은 Flutter analyzer 실행 결과를 뜻하지 않는다. 기존 검증 기록의 Flutter 187개·서버 124개 통과와 후속 집중 테스트 결과는 과거 실행 증거다.

## 최우선 조치

### P1 재가입 정리가 새 계정까지 삭제할 수 있는 경합

**코드 확인.** 서버 [auth.js](../../../APT-Prj/api/auth.js)의 70~84행은 탈퇴 상태와 7일 경과를 읽은 후 정리 함수를 호출한다. [db.js](../../../APT-Prj/api/_lib/db.js)의 910~922행은 계정 생성 시각·현재 상태를 다시 확인하지 않고 이메일만으로 여러 테이블과 계정을 삭제한다.

두 로그인 요청이 같은 탈퇴 계정을 읽고, A가 정리·신규 생성까지 끝낸 뒤 B의 삭제가 실행되면 신규 계정이나 연결 데이터가 삭제될 수 있다. 운영에서 발생했다는 증거는 확인하지 않았다.

**방향:** 계정 세대와 탈퇴 시각·7일 조건을 DB에서 재검사하고, 계정 잠금과 정리·재생성을 하나의 트랜잭션으로 처리한다. 기존 계정 삭제 함수의 조건부 삭제 방식을 재사용한다.

**완료 기준:** 독립 DB 연결 두 개로 정리와 재가입 순서를 교차시켜도 신규 계정·세션·신규 데이터가 유지되며, 중간 실패 시 부분 삭제가 남지 않는다. 담당 영역은 서버·DB다.

### P1 관리자 전체 저장이 다른 회원의 최신 입차를 덮어쓸 수 있음

**코드 확인.** 서버 [state.js](../../../APT-Prj/api/state.js) 124~128행은 관리자 입력 전체를 상태로 만들고, [member-management.sql](../../../APT-Prj/sql/member-management.sql) 160~185행은 일반 회원에게만 기존 타인 슬롯 병합을 적용한다. 관리자 요청에 예상 상태 버전 비교가 없다.

관리자가 화면을 연 뒤 다른 회원이 입차하고, 관리자가 오래된 전체 상태를 저장하면 중간 입차가 사라질 수 있다. DB 잠금만으로 오래된 입력의 덮어쓰기를 막을 수는 없다.

**방향:** 단일 슬롯 변경은 변경 슬롯·등록 ID만 전송하고, 지도 등 전체 저장은 `expectedVersion`을 검사해 불일치 시 409로 반환한다. 기존 클라이언트와의 계약 이행 순서를 포함해야 한다.

**완료 기준:** 관리자 A 조회 → 회원 B 입차 → A 저장 순서에서 B가 보존되거나 충돌을 명시적으로 반환한다. 관리자 2명의 동시 편집도 검사한다. 담당은 앱·웹·서버·DB다.

### P1 같은 계정의 조회와 변경 응답 순서가 화면을 되돌림

**코드 확인.** [app_state_provider.dart](../../lib/providers/app_state_provider.dart) 176~177, 205~208행은 계정 세대만 검사하고 조회·저장 결과를 적용한다. 256~258, 325~327행은 실패 시 전체 snapshot을 복원한다.

오래된 GET이 저장 성공 뒤 도착하거나, 병렬 변경 B 성공 뒤 A 실패가 도착하면 최신 화면과 캐시가 이전 상태로 돌아갈 수 있다. 이 항목 자체는 서버 데이터 손실을 확인한 결과가 아니다.

**방향:** 동일 계정 안에서도 조회·변경 revision을 구분하고, 변경은 직렬화하거나 슬롯별 작업 ID로 관리한다. 실패 복원은 해당 작업이 바꾼 범위만 대상으로 한다.

**완료 기준:** 지연 응답을 제어하는 기존 테스트 adapter로 GET/POST 역전, A 실패/B 성공, 출차·수신 선택 겹침을 검증한다. 기존 계정 전환 보호는 유지한다. 담당은 앱이다.

### P1 401과 권한 제한 응답이 인증 화면 상태에 반영되지 않음

**코드 확인.** [app_state_provider.dart](../../lib/providers/app_state_provider.dart) 184~187행은 API 오류 문구만 갱신한다. [auth_provider.dart](../../lib/providers/auth_provider.dart) 104~117행은 캐시가 있으면 비401 오류를 무시한다. 서버 차단 403을 받더라도 기존 승인 화면과 메모리 데이터가 유지되는 경로가 있다. 서버 권한 우회가 확인된 것은 아니다.

**방향:** 401과 계정 제한을 의미하는 `authStatus`를 인증 계층에 전달해 화면·캐시·진행 중 작업을 정리한다. 일반 작업 권한 403과 통신 장애를 모두 로그아웃으로 처리해서는 안 된다.

**완료 기준:** 사용 중 만료 401, 차단·탈퇴 403, 단순 작업 금지 403, 네트워크 장애를 각각 구분하고 계정 상태에 맞는 화면과 데이터 수명을 검증한다. 담당은 앱이다.

### P1 iOS Google 로그인 설정이 빠져 있음

**코드 확인 및 실행 미검증.** [auth_provider.dart](../../lib/providers/auth_provider.dart) 68~72행은 웹용 `serverClientId`만 전달한다. [Info.plist](../../ios/Runner/Info.plist)에는 iOS `GIDClientID`와 `CFBundleURLTypes`가 없으며, iOS Google 설정 파일도 확인되지 않았다. 설치된 `google_sign_in_ios` 문서의 iOS 클라이언트 ID와 복귀 scheme 요구사항을 충족시키지 못한다.

**방향:** 해당 bundle ID에 맞는 iOS 클라이언트 ID와 reversed URL scheme을 설정한다. Android용 웹 클라이언트 ID를 그대로 대체해서는 안 된다.

**완료 기준:** macOS 빌드와 실제 iPhone에서 신규·기존 로그인, 취소, 계정 전환, 앱 복귀, 서버 토큰 audience 검증을 통과한다. iOS 출시를 진행할 때의 선행 조건이다.

## 출시와 운영에서 남은 검증

- **통화 활성화 조건:** TURN 설정, 실제 Android/iOS 두 기기에서 서로 다른 Wi-Fi/LTE, 권한 거절·수락, 백그라운드 종료, 계정·주차 변경, 수신 OFF 전환, TURN 장애를 확인한다. 전경 전용이라는 기존 제품 범위는 유지한다.
- **iOS 링크·푸시:** Associated Domains와 서버 AASA를 갖춘 뒤 Universal Links를 검증한다. 현재 `Runner.entitlements`에는 APNs만 확인된다. APNs 자격·서명·알림 전달은 실기기 확인이 필요하다.
- **실제 장치 기능:** Google 로그인, 다양한 한국 번호판·야간·반사 사진 OCR, 카메라/시스템 선택기 복귀, BLE 검색·권한, QR/NFC 콜드·웜 진입을 장치와 OS별로 확인한다.
- **DB 복구:** 배포 rollback과 DB 데이터 복원은 다르다. 실제 Neon의 보존 기간, 목표 데이터 손실 시간(RPO), 복구 시간(RTO)을 확인하고 격리 환경에서 복원 훈련을 남긴다. 현재 설정이 없다고 단정한 것은 아니다.
- **화면 접근성:** 큰 글씨·가로 화면·키보드에서 전역 통화 패널과 종료 버튼을 확인한다. 높이 부족으로 실제 overflow가 발생했는지는 이번에 실행 재현하지 않았다.

최신 확인된 배포 기록에서 서버는 운영 전환 완료, Android21은 사진 권한 사전 검사 완료 후 Google 심사 중이며 관리형 게시가 켜져 있다. Google 승인·실제 최종 게시·구14 제공 종료를 완료로 간주하지 않는다. 이번 감사에서는 Console을 새로 조회하지 않았다. 기존 [21 검증 보고서](../verification/RELEASE_1.1.4_21_2026-10-21.md)와 [사진 권한 차단 수정 기록](../verification/PLAY_PHOTO_PERMISSION_BLOCKER_2026-10-21.md)을 따른다.

실행에 착수할 때는 버그별 최소 재현 테스트를 먼저 만들고 기존 검증 명령을 적용한다. Flutter는 `C:/src/flutter/bin/flutter.bat`을 사용하며 Windows의 한글 TEMP 문제를 피하는 기존 검증 환경 설정을 유지한다. 통화·플랫폼 변경은 단위 테스트만으로 완료 판정하지 않는다.

Flutter 공식 문서는 [앱 전체 흐름 통합 테스트](https://docs.flutter.dev/testing/integration-tests)와 [접근성 검사 API](https://docs.flutter.dev/ui/accessibility/accessibility-testing)를 제공한다. 해당 도구를 실제 기기 검증과 함께 사용해 현재 widget·단위 테스트의 빈 곳을 보완할 수 있다.

## 감사 진행 기록

PM의 기존 설치 스킬 선택 권한은 `cfg/blue-ocean.preferences.json`의 `pm`을 적용했다. Blue Ocean·project-diagram으로 범위를 나누고 기존 모바일·서버·화면 검토 에이전트가 읽기 전용 검토를 수행했으며, PM이 주요 소스를 대조하고 결과를 합쳤다. 기존 에이전트 모델 정보는 이번 턴에서 재검증하지 않았다. 빌드·테스트를 병렬로 실행하지 않았다. 문서 작성에는 write-page의 명확성·사실 범위 기준을 적용하되 저장소의 기존 Markdown 형식과 위치를 유지했다.

Blue Ocean upstream 확인: `BTL-LaserInnovation/Codex-Skill`, 기본 branch `master`, 스킬 경로 최신 commit `0657576558186f4a93391f972a019ec0a7a8413f`. 설치 revision은 알 수 없고 내용은 upstream과 다르다. 로컬 변경 가능성을 보존해 설치를 교체하지 않았다. 이번 분석은 설치 스킬 갱신에 의존하지 않으며 앱 프레임워크와 기존 사용자 지시를 우선했다.
